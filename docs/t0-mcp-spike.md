# T0 · 腾讯文档 SmartSheet MCP 能力验证

> **执行人：WorkBuddy**（仓库这边无法验证，必须在真实环境里跑）
> **目的**：在动手建表之前，确认 MCP 到底能做什么。
> **产出**：把下面每张表的「实测结果」列填掉，回填本文件并提交。

## 为什么要扩展 PRD 的 T0

PRD §37 的 T0 是四项：读取、新增、更新、创建字段。
这四项验证的是"能不能连上"，但连上之后仍有五个问题会直接决定 MVP-0 能不能做成，
而且都是**无声失效**——不报错，只是结果悄悄不对：

1. 多选字段的选项能不能由 MCP 固定？固定不了，整套冻结词表就只是一份文档，Agent 写什么都进得去。
2. 写入词表外的值会报错还是自动建选项？自动建 = 标签词表必然漂移。
3. 更新记录是局部更新还是整条覆盖？覆盖 = Quick Capture 更新 `recent_interests` 会抹掉 `profile_summary`。
4. CSV 导入时 `买菜生鲜;社区活动` 会拆成两个选项，还是变成一个叫"买菜生鲜;社区活动"的值？
   后者会让 25 条居民数据全部失真，而且表面上看不出来。
5. 一次读取能不能拿全 25 条居民？分页会让 Agent 只看到一部分人就出名单。

下面 A 组必须全部 PASS 才进入 Build；B 组只影响实现方式，不阻塞。

## A 组 · 阻塞项

在一张**临时测试表**里做，不要用正式的六张表。

| 编号 | 验证内容 | 具体做法 | PASS 标准 | 实测结果 |
|---|---|---|---|---|
| A1 | 读取记录 | 读取测试表全部记录 | 拿到全部字段值，字段名与表头一致 | |
| A2 | 新增记录 | 新增 1 条，含单行文本 / 多选 / 日期时间三种字段 | 三种字段都正确写入 | |
| A3 | 更新记录 | 对 A2 的记录，**只更新 1 个字段** | 其余字段保持原值不变 | |
| A4 | 创建字段 | 新建一个「单行文本」字段 | 字段出现且可写 | |
| A5 | 创建多选字段并固定选项 | 新建「多选」字段，预设 3 个选项 | 选项按预设生成 | |
| A6 | 写入词表外的值 | 向 A5 字段写入一个**不在**选项里的值 | **报错**为 PASS；**自动新建选项**为 FAIL（记为"需人工兜底"） | |
| A7 | 日期时间读写 | 写入 `2026-09-26 09:30`，再读回 | 读回的值和写入一致，时区没有偏移 | |
| A8 | 一次读满 25 条 | 测试表塞 25 条，一次性读取 | 一次拿到 25 条；若分页，记录每页条数 | |

### A3 如果 FAIL（整条覆盖）

Quick Capture 必须改成"先读整条 → 本地合并 → 整条写回"。
这不是大改动，但必须在 Prompt 里写死，否则演示时会当场丢数据。
请在实测结果里注明。

### A5 / A6 如果 FAIL

说明词表无法由系统强制。应对：

- 选项改由**运营人员在 SmartSheet 界面手工创建**（一次性工作，不阻塞）；
- Agent 侧靠 Prompt 约束 + `tools/validate_demo_data.py` 事后校验；
- 在演示前的彩排里增加一步：导出数据跑一次校验脚本。

### A7 如果 FAIL

日期是推荐规则第 0 步的依据（`expire_at`）。
如果时区有偏移，请记录**偏移量和方向**，我们在数据侧统一补偿。

| 编号 | 验证内容 | 具体做法 | 需要记录 | 实测结果 |

| B2 | 系统时间字段 | 查看是否有「创建时间」「最后修改时间」字段类型 | 能否创建、能否读取、能否被 MCP 写入 | |

| B5 | 视图创建 | 尝试用 MCP 建一个筛选视图 | 能 / 不能（不能就人工建，不阻塞） | |

### B1 的重要性

`demo/seed-data/` 的 6 个 CSV 全部用半角 `;` 分隔多选值。
如果导入工具不这么理解，需要在导入前做一次转换，**转换方式请在实测结果里写清楚**，
我们在仓库侧提供对应的转换脚本。

### B2 如果系统字段不可用

`Needs.created_at` / `updated_at` 改为普通日期时间字段，由运营在录入时填。
Agent 仍然不生成这两个值（PRD §29 的原则不变）。
`demo/seed-data/Needs.csv` 目前**不含**这两列，就是为了等这个结论。

## 回填格式

每项填 `PASS` / `FAIL` / `部分`，后面跟一句话说明。例：

```text
A3 | PASS | 局部更新，其余字段不受影响
A6 | FAIL | 写入词表外的值会自动新建选项，不报错
B1 | 部分 | 分号被当成普通字符，需要改用换行分隔
```

## PASS 之后

A 组全绿即可进入 Build，顺序见 `docs/sheet-setup.md`。
如果 A 组有 FAIL，先把应对写进本文件，再决定是否开工——
**不要带着未确认的假设建表**，返工的成本比多花半小时验证高得多。
